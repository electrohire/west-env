# Zephyr 4.0.0 — version overlay for the Beningo Zephyr skills

This file is the per-version adjustment layer for the five Beningo
Zephyr skills shipped in this image (build-doctor, devicetree-author,
kconfig-tuner, renode-runner, zephyr-bsp-scaffold). The skills
themselves are version-agnostic across Zephyr 4.x; read this overlay
first and let it override any assumption in a skill that conflicts
with the facts below. The image build copies this file to
/opt/zephyr-skills/version-overlay.md.

## What this image actually contains

- Zephyr: exactly v4.0.0. The Python requirements installed are this
  release's own scripts/requirements.txt, nothing unioned from other
  releases.
- Zephyr SDK: exactly 0.17.0, the pin in this release's SDK_VERSION
  file. The SDK ships as one monolithic tarball and is installed at
/opt/zephyr-sdk by its setup.sh with `-t all`, so every supported
architecture toolchain is present.
- Board model: hardware model v2 (board.yml with SoC qualifiers),
  as in every Zephyr 4.x release. The bsp-scaffold four-file shape
  (board.yml, .dts, Kconfig.<board>, _defconfig, pinctrl) applies
  as written.
- Workspace layout in the container: /work is the west workspace
  topdir; the Zephyr tree is the workspace's zephyr project, not a
  fixed /workdir/zephyr path.

## Skill-specific notes for this version

- Toolchains: all architectures from the monolithic SDK are
  installed; ZEPHYR_TOOLCHAIN_VARIANT=zephyr.
- build-doctor: an SDK or requirements mismatch is not a plausible
  cause inside this image; the SDK is this release's own pin. Look
  first at workspace-side causes (overlay, binding, Kconfig).
- renode-runner: the boot banner in the skill's example log is
  illustrative only; this image's builds banner v4.0.0.
- kconfig-tuner / devicetree-author: verify every symbol and binding
  against this image's Zephyr v4.0.0 tree (grep-or-refuse still
  governs); symbols and bindings differ between 4.x releases.
